# IconButton

An icon-only pressable, sharing `Button`'s `primary`/`secondary` variants and color tokens. Use it
for compact actions where a visible label isn't needed — `accessibilityLabel` is required, since
there's no text to fall back on for assistive tech.

## Tokens

- `colors.primary` — primary: background
- `colors.primaryDisabled` — primary: background (disabled)
- `colors.primaryPressed` — primary: background (selected)
- `colors.textOnPrimary` — primary: icon color
- `colors.secondaryBackground` — secondary: background
- `colors.primaryPressed` — secondary: background (selected)
- `colors.secondaryBorder` — secondary: border
- `colors.secondaryText` — secondary: icon color
- `colors.textOnPrimary` — secondary: icon color (selected)
- `opacity.disabled` — both: disabled dimming
- `radii.xs` — both: corner radius
- `sizes.touchMin` — both: width / height

## States

`disabled`, `loading` (spinner in place of the icon, implies disabled, sets
`aria-busy`/`accessibilityState.busy`), and `selected` (toggled/active, exposed as
`aria-pressed`/`accessibilityState.selected`).

## accessibilityHint

Same behavior as `Button`'s — optional supplemental context for when the label alone doesn't
convey the result. Especially relevant for destructive icon-only actions, where the icon and
label alone may not fully convey the consequence:

<Canvas of={IconButtonStories.WithAccessibilityHint} />

## Extra props

Same as `Button`: any other native `<button>`/`Pressable` prop is forwarded. `style`, `disabled`,
`type` (fixed to `"button"`), and the internal press handlers (`onMouseDown`/`onMouseUp`/
`onMouseLeave` web, `onPressIn`/`onPressOut` native) aren't overridable — use `onPress`.
